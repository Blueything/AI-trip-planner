# Travel Planner

A React and Supabase web app for planning multi stop trips. A signed in user
searches destinations, drags stops into order on a Leaflet map, sets a budget,
saves the trip, and shares a read only link with someone who has no account.

![Travel Planner](Project-Image.png)

## What works today

* Email and password auth with automatic profile creation and persisted sessions
* Trip create, edit and delete, scoped to the signed in owner
* Destination search across a seeded catalogue with live OpenStreetMap Nominatim lookup as the fallback
* Drag to reorder itinerary stops, each with its own day count and note
* End date derived automatically from the start date plus total stop durations
* Interactive Leaflet map with markers, a route line, and four switchable tile styles
* Budget estimator splitting a total across accommodation, food, transport, activities, shopping and miscellaneous, weighted by travel style
* Personal analytics dashboard in Recharts: trip totals, stops by country, monthly volume
* Reviews with ratings, tags and location metadata
* Public trip sharing through a token generated by a Postgres trigger

## Not yet wired, stated plainly

* The chat assistant persists real sessions but returns a fixed reply, because no model provider is connected
* The weather panel shows generated sample values rather than calling a weather API
* Flight search calls the real Amadeus endpoint through an edge function, but needs API credentials set as secrets before it returns results

## How it works

`src/main.tsx` mounts `App.tsx`, which nests the query client, the auth provider
and the router. `Layout.tsx` reads the session and sends signed out visitors to
the auth route, though that redirect is convenience rather than the security
boundary. The planner page holds trip state in React, renders the sidebar beside
the map, and writes the stop list to a JSON column on the `trips` table. A
Postgres trigger fills `share_token`, and the shared route reads a trip by that
token with no session at all. Flight search runs inside a Supabase Edge Function
so the Amadeus OAuth secret never reaches the browser bundle.

Row Level Security does the real access control: trips, chat sessions,
preferences and suggestions scope to `auth.uid()`, while reviews and the
destination catalogue are readable by everyone.

## Data model

Seven Postgres tables: profiles, trips, reviews, chat_sessions, user_preferences,
popular_destinations, trip_suggestions. Two database functions, ten migration
files, one edge function.

## Stack

React 18.3.1, Vite 5.4.19, TypeScript 5.8.3, Tailwind CSS 3.4.17, Radix UI
primitives, Leaflet 1.9.4, Recharts 2.15.4, dnd kit, date fns, Supabase Postgres,
Supabase Auth, one Supabase Edge Function, OpenStreetMap Nominatim, Amadeus.

## Notes on the build

Stops are stored as a JSON array on the trip rather than in a child table,
because reordering rewrites the whole list on every drag and one update writes
it. The cost is that no query can filter on an individual stop, so the analytics
view counts stops in JavaScript.

Sharing uses an unguessable token minted by a trigger, paired with a policy that
allows a read when the token matches. That keeps the row id private and lets the
link be revoked at the column level. The token is a bearer secret, so anyone who
forwards the link keeps access.

Destination search merges the local catalogue with Nominatim, local first,
because the seeded rows carry a rating, a budget per day and best months that
Nominatim does not return.
